CPU Scheduling Algorithms Explained

10 min read • CPU Scheduling • Critical

Introduction

CPU scheduling is one of the most important functions of an operating system. It determines which process gets to use the CPU and for how long. Understanding scheduling algorithms is crucial for OS interviews and system design.

What is CPU Scheduling?

CPU scheduling is the process of selecting which ready process should be allocated the CPU next. The scheduler makes this decision to maximize CPU utilization and system throughput while minimizing response time and waiting time.

Key Scheduling Criteria

Before diving into algorithms, let's understand the metrics used to evaluate them:

  • CPU Utilization: Percentage of time the CPU is busy (goal: maximize)
  • Throughput: Number of processes completed per time unit (goal: maximize)
  • Turnaround Time: Total time from submission to completion (goal: minimize)
  • Waiting Time: Time spent in the ready queue (goal: minimize)
  • Response Time: Time from submission until first response (goal: minimize)

1. First-Come, First-Served (FCFS)

How It Works

The simplest scheduling algorithm. Processes are executed in the order they arrive in the ready queue, like customers in a line at a store.

Characteristics

  • Non-preemptive: Once CPU is allocated, process runs to completion
  • Easy to implement using FIFO queue
  • Suffers from convoy effect

Convoy Effect

When a long process arrives first, all shorter processes must wait. This significantly increases average waiting time. Imagine waiting behind someone with a full cart at a grocery store!

Example

Process Arrival Time Burst Time P1 0 24 P2 1 3 P3 2 3 Execution Order: P1 → P2 → P3 Waiting Time: P1: 0 P2: 24 - 1 = 23 P3: 27 - 2 = 25 Average Waiting Time: (0 + 23 + 25) / 3 = 16 ms

Pros and Cons

  • ✅ Simple to understand and implement
  • ✅ No starvation (all processes eventually execute)
  • ❌ Poor average waiting time
  • ❌ Convoy effect reduces CPU utilization
  • ❌ Not suitable for time-sharing systems

2. Shortest Job First (SJF)

How It Works

Selects the process with the smallest execution time (burst time) next. Provides optimal average waiting time for a given set of processes.

Types

  • Non-preemptive SJF: Once started, process runs to completion
  • Preemptive SJF (SRTF - Shortest Remaining Time First): If a new process arrives with shorter burst time than remaining time of current process, preempt current process

Example (Non-preemptive)

Process Arrival Time Burst Time P1 0 7 P2 2 4 P3 4 1 P4 5 4 Execution Order: P1 → P3 → P2 → P4 Average Waiting Time: 4 ms (much better than FCFS!)

Pros and Cons

  • ✅ Optimal average waiting time
  • ✅ Minimizes average turnaround time
  • ❌ Difficult to predict burst time accurately
  • ❌ Can cause starvation of long processes
  • ❌ Not implementable in practice (burst time unknown)

Burst Time Prediction

Since we can't know exact burst time, we estimate using exponential averaging:

τ(n+1) = α × t(n) + (1-α) × τ(n)

where τ is predicted time, t is actual time, and α is a weight (typically 0.5)

3. Priority Scheduling

How It Works

Each process is assigned a priority, and the CPU is allocated to the process with the highest priority. Equal-priority processes are scheduled using FCFS.

Priority Assignment

  • Internal priorities: Based on measurable quantities (time limits, memory requirements, resources needed)
  • External priorities: Set by criteria external to OS (importance of process, user privileges, funding)

Example

Process Burst Time Priority (lower number = higher priority) P1 10 3 P2 1 1 P3 2 4 P4 1 5 P5 5 2 Execution Order: P2 → P5 → P1 → P3 → P4

The Starvation Problem

Low-priority processes may wait indefinitely if high-priority processes keep arriving.

Solution: Aging

Gradually increase the priority of processes that wait in the system for a long time. This ensures that even low-priority processes eventually get executed.

Pros and Cons

  • ✅ Flexible - can implement various policies
  • ✅ Good for real-time systems
  • ✅ Can differentiate between process types
  • ❌ Can lead to starvation
  • ❌ Priority inversion problem
  • ❌ Defining appropriate priorities is challenging

4. Round Robin (RR)

How It Works

Designed specifically for time-sharing systems. Each process gets a small time unit called a time quantum (or time slice). After the quantum expires, the process is preempted and added to the end of the ready queue.

Characteristics

  • Preemptive version of FCFS
  • Ready queue is circular (hence "round robin")
  • Performance heavily depends on time quantum size

Example (Time Quantum = 4ms)

Process Burst Time P1 24 P2 3 P3 3 Execution: P1(4) → P2(3) → P3(3) → P1(4) → P1(4) → P1(4) → P1(4) → P1(4) Average Waiting Time: 5.66 ms

Choosing Time Quantum

  • Too large: Becomes FCFS (poor response time)
  • Too small: Too many context switches (high overhead)
  • Optimal: 10-100 milliseconds typically
  • Rule of thumb: 80% of CPU bursts should be shorter than time quantum

Pros and Cons

  • ✅ Fair allocation of CPU time
  • ✅ Good response time
  • ✅ No starvation
  • ✅ Works well for time-sharing systems
  • ❌ Higher average turnaround time than SJF
  • ❌ Performance depends on time quantum
  • ❌ Context switching overhead

5. Multilevel Queue Scheduling

How It Works

Processes are permanently assigned to different queues based on their properties (process type, memory size, priority). Each queue has its own scheduling algorithm.

Typical Queue Division

  • System processes: Highest priority
  • Interactive processes: High priority, Round Robin
  • Interactive editing processes: Medium priority
  • Batch processes: Low priority, FCFS
  • Student processes: Lowest priority

Queue Scheduling

Two approaches for scheduling between queues:

  • Fixed Priority: Serve all from higher priority queue first (can cause starvation)
  • Time Slicing: Each queue gets a certain amount of CPU time (e.g., 80% to foreground, 20% to background)

Example Distribution

Foreground (interactive): 80% CPU time using Round Robin

Background (batch): 20% CPU time using FCFS

Pros and Cons

  • ✅ Separates processes by type
  • ✅ Different algorithms for different process types
  • ✅ Low scheduling overhead
  • ❌ Inflexible (processes can't move between queues)
  • ❌ May lead to starvation

6. Multilevel Feedback Queue Scheduling

How It Works

An extension of multilevel queue where processes can move between queues based on their behavior. This is the most general and complex scheduling algorithm.

Key Characteristics

  • Multiple queues with different priorities
  • Processes can move between queues
  • Aging is implemented to prevent starvation
  • CPU-bound processes move to lower-priority queues
  • I/O-bound processes stay in higher-priority queues

Example Configuration

Queue 0: RR with quantum = 8ms Queue 1: RR with quantum = 16ms Queue 2: FCFS Rules: - New process enters Q0 - If process doesn't finish in 8ms, move to Q1 - If doesn't finish in 16ms at Q1, move to Q2 - Process completing I/O returns to Q0

Parameters to Define

  • Number of queues
  • Scheduling algorithm for each queue
  • Method to determine when to upgrade a process
  • Method to determine when to demote a process
  • Method to determine which queue a new process enters

Pros and Cons

  • ✅ Most flexible scheduling algorithm
  • ✅ Adapts to process behavior
  • ✅ Favors short processes and I/O-bound processes
  • ✅ Prevents starvation through aging
  • ❌ Most complex to implement
  • ❌ Difficult to configure optimally
  • ❌ Requires tuning for specific workloads

Algorithm Comparison

Algorithm Preemptive Starvation Average WT Complexity Best Use Case
FCFS No No High Low Batch systems
SJF Optional Yes (long processes) Optimal Medium When burst time known
Priority Optional Yes (without aging) Medium Medium Real-time systems
Round Robin Yes No Medium Low Time-sharing systems
Multilevel Queue Optional Possible Medium Medium Mixed workloads
Multilevel Feedback Yes No (with aging) Low-Medium High General-purpose OS

Common Interview Questions

1. What is the difference between preemptive and non-preemptive scheduling?

Answer: In preemptive scheduling, the OS can interrupt a running process and allocate the CPU to another process. In non-preemptive scheduling, once a process starts execution, it runs until completion or until it voluntarily releases the CPU (I/O or termination).

2. Why is SJF considered optimal?

Answer: SJF gives the minimum average waiting time for a given set of processes. However, it's not implementable in practice because we can't know the exact burst time in advance.

3. What is the purpose of time quantum in Round Robin?

Answer: The time quantum determines how long each process can execute before being preempted. It balances between response time and context switching overhead. Too small causes excessive switching; too large makes it behave like FCFS.

4. How does Multilevel Feedback Queue prevent starvation?

Answer: Through aging - processes that wait too long gradually have their priority increased, ensuring they eventually get CPU time.

5. Which scheduling algorithm is used in modern operating systems?

Answer: Most modern operating systems use variations of Multilevel Feedback Queue scheduling. For example, Linux uses the Completely Fair Scheduler (CFS), and Windows uses a priority-based multilevel feedback queue system.

Summary

CPU scheduling is fundamental to OS performance. Each algorithm has trade-offs:

  • FCFS: Simple but inefficient
  • SJF: Optimal but impractical
  • Priority: Flexible but can starve processes
  • Round Robin: Fair and good for interactive systems
  • Multilevel Feedback Queue: Most sophisticated and widely used

Understanding these algorithms helps you design better systems and ace OS interviews!
