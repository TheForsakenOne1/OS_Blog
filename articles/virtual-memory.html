Virtual Memory and Page Replacement Algorithms

13 min read • Virtual Memory

Introduction

Virtual memory is a memory management technique that provides an idealized abstraction of storage. It allows programs to use more memory than physically available and enables efficient process execution even when only partially loaded in memory.

Key Benefit

Virtual memory separates logical memory (programmer's view) from physical memory (actual RAM). This separation provides enormous flexibility in memory management!

Demand Paging

The foundation of virtual memory. Pages are loaded into memory only when they are demanded during program execution.

How It Works

  • Process starts with no pages in memory
  • Pages are brought into memory only when referenced
  • Uses lazy loading strategy
  • Requires hardware support: valid-invalid bit

Valid-Invalid Bit

Valid (v): Page is in memory Invalid (i): Page is not in memory or not in logical address space Initially all entries are set to invalid When page is brought into memory, bit is set to valid

Page Fault

When a process tries to access a page not in memory:

1. Reference to page with invalid bit causes page fault 2. OS checks internal table: - Invalid reference? → Abort process - Valid but not in memory? → Bring it in 3. Find free frame 4. Read page from disk into frame 5. Update page table (set valid bit) 6. Restart instruction that caused page fault

Performance Impact

Memory access time = 200 nanoseconds Page fault time = 8 milliseconds = 8,000,000 ns EAT = (1 - p) × 200 + p × 8,000,000 where p = page fault rate If p = 0.001 (1 fault per 1000 accesses): EAT = 0.999 × 200 + 0.001 × 8,000,000 = 199.8 + 8,000 = 8,199.8 ns (40x slower!) To keep degradation < 10%: Need p < 0.0000025 (1 in 400,000)

Critical Point

Page fault rate has HUGE impact on performance. Even very low page fault rates can significantly slow down the system!

Page Replacement Algorithms

When a page fault occurs and no free frames are available, we must select a victim page to replace.

Goal

Minimize page fault rate to achieve best performance.

Reference String

Sequence of page numbers accessed by a process. Used to evaluate page replacement algorithms.

Example: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1 With 3 frames, how many page faults occur with different algorithms?

1. FIFO (First-In-First-Out)

Algorithm

  • Replace the oldest page (first one brought in)
  • Easy to implement using a queue
  • Fair but not optimal

Example

Reference String: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 Frames: 3 Step-by-step: 1: [1] - Fault 2: [1,2] - Fault 3: [1,2,3] - Fault 4: [4,2,3] - Fault (replace 1) 1: [4,1,3] - Fault (replace 2) 2: [4,1,2] - Fault (replace 3) 5: [5,1,2] - Fault (replace 4) 1: [5,1,2] - Hit 2: [5,1,2] - Hit 3: [5,3,2] - Fault (replace 1) 4: [5,3,4] - Fault (replace 2) 5: [5,3,4] - Hit Total: 9 page faults

Belady's Anomaly

Surprising Finding!

For some page reference strings, increasing the number of frames can INCREASE page faults! This is unique to FIFO.

Example: With 3 frames = 9 faults, but with 4 frames = 10 faults!

Pros and Cons

  • ✅ Simple to implement
  • ✅ Fair (all pages get equal chance)
  • ❌ Poor performance (doesn't consider usage patterns)
  • ❌ Suffers from Belady's Anomaly
  • ❌ May replace frequently used pages

2. Optimal Page Replacement

Algorithm

  • Replace page that will not be used for longest time in future
  • Guarantees lowest page fault rate
  • Used as benchmark to compare other algorithms

Example

Reference String: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2 Frames: 3 Step-by-step: 7: [7] - Fault 0: [7,0] - Fault 1: [7,0,1] - Fault 2: [2,0,1] - Fault (replace 7, won't be used until far future) 0: [2,0,1] - Hit 3: [2,0,3] - Fault (replace 1, used farthest in future) 0: [2,0,3] - Hit 4: [4,0,3] - Fault (replace 2, will be used next, so keep 0 and 3) 2: [4,0,2] - Fault (replace 3) 3: [4,3,2] - Fault (replace 0) 0: [0,3,2] - Fault (replace 4) 3: [0,3,2] - Hit 2: [0,3,2] - Hit Total: 9 page faults (optimal!)

The Problem

Not Implementable!

Optimal algorithm requires knowledge of future page references, which is impossible in practice. It's used only as a theoretical benchmark.

3. LRU (Least Recently Used)

Algorithm

  • Replace page that hasn't been used for longest time
  • Based on principle of locality
  • Approximates optimal algorithm using past instead of future
  • Does not suffer from Belady's Anomaly

Example

Reference String: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2 Frames: 3 7: [7] - Fault 0: [7,0] - Fault 1: [7,0,1] - Fault 2: [2,0,1] - Fault (replace 7, LRU) 0: [2,0,1] - Hit 3: [2,0,3] - Fault (replace 1, LRU) 0: [2,0,3] - Hit 4: [4,0,3] - Fault (replace 2, LRU) 2: [4,0,2] - Fault (replace 3, LRU) 3: [4,3,2] - Fault (replace 0, LRU) 0: [0,3,2] - Fault (replace 4, LRU) 3: [0,3,2] - Hit 2: [0,3,2] - Hit Total: 9-10 page faults (near optimal!)

Implementation Methods

1. Counter Implementation:

  • Associate counter with each page table entry
  • Increment counter on each memory reference
  • Replace page with smallest counter
  • ❌ Requires searching all counters
  • ❌ Overflow issues

2. Stack Implementation:

  • Keep stack of page numbers
  • When page referenced, move to top
  • LRU page is always at bottom
  • ✅ No search needed
  • ❌ Expensive to update (need to change pointers)

Pros and Cons

  • ✅ Excellent performance (close to optimal)
  • ✅ No Belady's Anomaly
  • ✅ Exploits temporal locality
  • ❌ Expensive to implement exactly
  • ❌ Requires hardware support

4. LRU Approximation Algorithms

Since true LRU is expensive, systems use approximations.

Reference Bit Algorithm

  • Each page has a reference bit
  • Initially all bits = 0
  • When page referenced, bit set to 1
  • Replace any page with reference bit = 0
  • Don't know the order of use

Second-Chance (Clock) Algorithm

  • FIFO with reference bit
  • When page selected for replacement:
    • If reference bit = 0 → Replace
    • If reference bit = 1 → Give second chance (set bit to 0, move to end)
  • Uses circular queue (clock hand)
Example: Pages: A(1), B(0), C(1), D(0) Clock hand at A Need to replace: A: bit=1 → Set to 0, move hand to B B: bit=0 → Replace B!

Enhanced Second-Chance

Uses both reference bit and modify bit: (reference, modify)

Priority (best to worst): (0, 0): Not recently used, not modified - BEST (0, 1): Not recently used, but modified (1, 0): Recently used, not modified (1, 1): Recently used and modified - WORST

5. Counting Algorithms

LFU (Least Frequently Used)

  • Replace page with smallest count
  • Intuition: Actively used pages have large reference counts
  • ❌ Problem: Page used heavily initially but not now has high count

MFU (Most Frequently Used)

  • Replace page with largest count
  • Intuition: Page with smallest count probably just brought in
  • ❌ Generally worse than LFU

Both are expensive and not commonly used.

Thrashing

When a process spends more time paging than executing.

Cause

  • Process doesn't have enough frames
  • Page fault → Replace page → Fault on replaced page → Replace again
  • CPU utilization drops
  • OS thinks it needs more multiprogramming
  • Adds more processes → More thrashing!

Death Spiral

Low CPU utilization → Add more processes → Even more page faults → Even lower CPU utilization → System grinds to halt!

Solution 1: Working Set Model

  • Working Set: Set of pages currently being used
  • Based on principle of locality
  • Working set window (Δ): Most recent page references
  • If total working set > total frames → Thrashing
  • Action: Suspend some processes

Solution 2: Page Fault Frequency (PFF)

  • Monitor page fault rate
  • If too high → Allocate more frames
  • If too low → Remove frames
  • If can't allocate more frames → Suspend process

Frame Allocation

Minimum Number of Frames

Must allocate enough frames to hold all pages referenced by a single instruction!

Allocation Algorithms

Equal Allocation:

m frames, n processes Each process gets m/n frames Simple but ignores process sizes

Proportional Allocation:

Process size: si Total size: S = Σ si Frames for process pi = (si / S) × m Example: Process 1: 64KB Process 2: 128KB Total frames: 64 P1 gets: (64/192) × 64 = 21 frames P2 gets: (128/192) × 64 = 43 frames

Global vs Local Replacement

  • Global: Process can select replacement from all frames
    • ✅ Better throughput
    • ❌ Process can't control its own page fault rate
  • Local: Process selects only from its own frames
    • ✅ Predictable performance
    • ❌ Possibly underutilizes memory

Common Interview Questions

1. What is the difference between paging and virtual memory?

Answer: Paging is a memory management technique that eliminates external fragmentation by using fixed-size pages. Virtual memory is a broader concept that allows execution of processes not completely in memory, using paging or segmentation as implementation techniques. Virtual memory provides the abstraction of unlimited memory.

2. Why is LRU better than FIFO?

Answer: LRU exploits temporal locality - recently used pages are likely to be used again. FIFO ignores usage patterns and may replace frequently used pages just because they're old. LRU doesn't suffer from Belady's Anomaly.

3. Why can't we implement optimal page replacement?

Answer: Optimal algorithm requires knowledge of future page references, which is impossible to know in advance. It's only used as a theoretical benchmark.

4. What is thrashing and how do you detect it?

Answer: Thrashing occurs when a process spends more time paging than executing. Detect by monitoring: high page fault rate, low CPU utilization, high disk I/O for paging. Solutions include working set model or page fault frequency scheme.

5. What is demand paging?

Answer: Demand paging loads pages into memory only when they're needed (demanded), rather than loading entire program at startup. It's the foundation of virtual memory and enables running programs larger than physical memory.

Algorithm Comparison

Algorithm Performance Implementation Belady's Anomaly Usage
FIFO Poor Easy Yes Rarely
Optimal Best Impossible No Benchmark only
LRU Excellent Expensive No Common (approximated)
Second-Chance Good Moderate No Very common
LFU/MFU Variable Expensive No Rare

Summary

Virtual memory is a powerful abstraction:

  • Demand paging: Load pages only when needed
  • Page replacement: Critical when physical memory full
  • LRU: Best practical algorithm (approximated in real systems)
  • Thrashing: Major performance issue, needs careful management
  • Modern systems: Use LRU approximations like Second-Chance/Clock
