Deadlock: Detection, Prevention & Recovery

12 min read • Deadlock

Introduction

Deadlock is one of the most critical problems in operating systems and concurrent programming. It occurs when a set of processes are blocked, each waiting for a resource held by another process in the set. Understanding deadlock is essential for system design and is a favorite interview topic.

Real-World Analogy

Imagine a narrow bridge where cars can only go one direction at a time. If two cars enter from opposite ends simultaneously and meet in the middle, neither can proceed. They're deadlocked!

Necessary Conditions for Deadlock

A deadlock situation can arise if and only if ALL four conditions hold simultaneously:

1. Mutual Exclusion

  • At least one resource must be held in a non-sharable mode
  • Only one process can use the resource at a time
  • Example: A printer can only be used by one process at a time

2. Hold and Wait

  • A process must be holding at least one resource
  • And waiting to acquire additional resources held by other processes
  • Example: Process P1 holds Resource A and waits for Resource B

3. No Preemption

  • Resources cannot be forcibly taken from a process
  • Resources are released only voluntarily by the process holding them
  • Example: A process holding a file lock cannot be forced to release it

4. Circular Wait

  • There exists a circular chain of processes
  • Each process holds a resource needed by the next process in the chain
  • Example: P1 waits for P2, P2 waits for P3, P3 waits for P1

Important Note

All four conditions must be present for deadlock to occur. If you can prevent even one of these conditions, you can prevent deadlock!

Resource Allocation Graph (RAG)

A visual tool to detect deadlock. The graph contains two types of nodes:

  • Process nodes: Represented as circles (P1, P2, etc.)
  • Resource nodes: Represented as rectangles (R1, R2, etc.)

Types of Edges

  • Request Edge: Directed edge from process to resource (Pi → Rj) - process requests resource
  • Assignment Edge: Directed edge from resource to process (Rj → Pi) - resource assigned to process

Detecting Deadlock with RAG

If graph contains NO cycles → No deadlock If graph contains a cycle: - If only one instance per resource type → Deadlock - If multiple instances → Possibility of deadlock

Example Deadlock Scenario

P1 holds R1, requests R2
P2 holds R2, requests R1

This creates a cycle: P1 → R2 → P2 → R1 → P1
Result: DEADLOCK!

Deadlock Prevention

Prevent deadlock by ensuring at least one of the four necessary conditions cannot hold.

1. Prevent Mutual Exclusion

  • Approach: Make resources sharable
  • Problem: Not possible for non-sharable resources (printers, locks)
  • Example: Read-only files can be shared, but write access cannot

2. Prevent Hold and Wait

Method 1: Require processes to request all resources at once

  • ✅ Prevents deadlock
  • ❌ Low resource utilization (resources held unnecessarily)
  • ❌ Starvation possible (process waiting for multiple resources)

Method 2: Require process to release all held resources before requesting new ones

  • ✅ Prevents deadlock
  • ❌ Resources may be needed throughout execution

3. Prevent No Preemption

Allow resource preemption:

  • If a process requests a resource that cannot be immediately allocated, it releases all currently held resources
  • Resources are added to the list of resources the process is waiting for
  • Process restarts only when it can acquire all needed resources
  • Issue: Only applicable to resources whose state can be saved/restored (CPU, memory), not for printers or mutex locks

4. Prevent Circular Wait

Method: Impose total ordering on resource types

Example: Assign numbers to resources (R1=1, R2=2, R3=3, etc.) Rule: Process must request resources in increasing order If process needs R1 and R5: ✅ Request R1 first, then R5 ❌ Cannot request R5 first, then R1 This prevents circular wait!
  • ✅ Practically implementable
  • ❌ May be inconvenient for programmers
  • ❌ Resource numbering must be carefully designed

Deadlock Avoidance

Requires additional information about how resources will be requested. The most famous algorithm is the Banker's Algorithm.

Banker's Algorithm

Named after the banking system where banks never allocate all cash to customers simultaneously. The algorithm ensures the system stays in a "safe state."

Key Concepts

  • Safe State: System can allocate resources to each process in some order and avoid deadlock
  • Unsafe State: No guarantee that deadlock can be avoided
  • Safe Sequence: Order of process execution that avoids deadlock

Data Structures

n = number of processes m = number of resource types Available[m]: Available instances of each resource Max[n][m]: Maximum demand of each process Allocation[n][m]: Currently allocated resources to each process Need[n][m]: Remaining resource need of each process Need[i][j] = Max[i][j] - Allocation[i][j]

Safety Algorithm

1. Initialize: Work = Available Finish[i] = false for all i 2. Find an index i such that: Finish[i] == false AND Need[i] <= Work If no such i exists, go to step 4 3. Work = Work + Allocation[i] Finish[i] = true Go to step 2 4. If Finish[i] == true for all i: System is in SAFE state Else: System is in UNSAFE state

Example

Processes: P0, P1, P2, P3, P4 Resources: A=10, B=5, C=7 Allocation Max Need Available A B C A B C A B C A B C P0 0 1 0 7 5 3 7 4 3 3 3 2 P1 2 0 0 3 2 2 1 2 2 P2 3 0 2 9 0 2 6 0 0 P3 2 1 1 2 2 2 0 1 1 P4 0 0 2 4 3 3 4 3 1 Safe Sequence: P1 → P3 → P4 → P2 → P0 Therefore, system is in SAFE state!

Pros and Cons

  • ✅ No deadlock can occur
  • ✅ Maximum resource utilization possible
  • ❌ Requires advance knowledge of maximum resource needs
  • ❌ Number of processes must be fixed
  • ❌ Resources must be fixed
  • ❌ High overhead for checking safety
  • ❌ Rarely used in practice

Deadlock Detection

Allow deadlock to occur, but detect and recover from it.

Single Instance Resources

Use wait-for graph (variant of RAG):

  • Remove resource nodes
  • Direct edges from Pi to Pj if Pi is waiting for a resource held by Pj
  • Deadlock exists if and only if graph contains a cycle
  • Detection: Run cycle detection algorithm periodically (O(n²) time)

Multiple Instance Resources

Similar to Banker's algorithm but without Need matrix:

Available[m]: Available instances Allocation[n][m]: Current allocation Request[n][m]: Current requests Detection algorithm similar to safety algorithm

When to Invoke Detection

  • Frequency: How often to check for deadlock
  • Trade-off: Frequent checks = high overhead, Infrequent = delayed detection
  • Strategies:
    • Every time a request cannot be granted
    • At fixed time intervals
    • When CPU utilization drops below threshold

Deadlock Recovery

Once deadlock is detected, we need to recover from it.

1. Process Termination

Option A: Abort all deadlocked processes

  • ✅ Simple and effective
  • ❌ Significant cost - processes lose all computation done so far

Option B: Abort one process at a time

  • Abort processes one by one until deadlock cycle is eliminated
  • After each abort, rerun detection algorithm
  • ❌ High overhead (detection after each abortion)

Process Selection Criteria

Which process to abort? Consider:

  • Process priority
  • How long process has executed
  • Resources used and needed
  • Number of processes to be terminated
  • Interactive vs batch process

2. Resource Preemption

Take resources from some processes and give to others.

Three Issues to Address

a) Selecting a Victim:

  • Which resources and which processes to preempt?
  • Minimize cost (number of resources, execution time)

b) Rollback:

  • If resource is preempted from a process, what to do with that process?
  • Total rollback: Restart process from beginning
  • Partial rollback: Roll back to safe state
  • Requires system to maintain state information

c) Starvation:

  • How to ensure the same process is not always picked as victim?
  • Solution: Include number of rollbacks in cost factor
  • Limit rollbacks per process

Combined Approach

Many systems use different strategies for different resource types:

Resource Type Strategy ------------------------------------------ Internal resources Prevention via ordering (CPU, memory) Main memory Avoidance via Banker's Job resources Avoidance (files, databases) PCB, semaphores Prevention

Common Interview Questions

1. Can deadlock occur with only one process?

Answer: No. Deadlock requires circular wait, which needs at least two processes.

2. What's the difference between deadlock prevention and avoidance?

Answer: Prevention ensures at least one necessary condition for deadlock cannot hold (restricts resource requests). Avoidance allows all conditions but makes intelligent resource allocation decisions using future knowledge (like Banker's algorithm).

3. Why is Banker's algorithm not commonly used in practice?

Answer: Because it requires:

  • Fixed number of processes
  • Fixed number of resources
  • Processes to declare maximum needs in advance
  • High computational overhead
These requirements are rarely met in real systems.

4. What does "safe state" mean?

Answer: A state where the system can allocate resources to each process in some order and still avoid deadlock. There exists at least one safe sequence. Note: Safe state ≠ No deadlock currently, it means deadlock can be avoided.

5. How does the Ostrich algorithm handle deadlock?

Answer: It ignores the problem! Used when deadlock is very rare, and the cost of prevention/avoidance/detection is higher than occasionally rebooting the system. Many operating systems (including UNIX) use this for certain resource types.

Summary

Deadlock handling strategies:

  • Ignore: Ostrich algorithm (used when rare)
  • Prevention: Negate one of four necessary conditions
  • Avoidance: Use Banker's algorithm (requires future knowledge)
  • Detection & Recovery: Allow deadlock, detect, and fix

Most real systems use a combination of approaches for different resource types!
