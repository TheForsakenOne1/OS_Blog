Memory Management: From Basics to Advanced

11 min read • Memory Management

Introduction

Memory management is one of the most critical functions of an operating system. It involves managing the computer's memory hierarchy, allocating memory to processes, and ensuring efficient utilization while preventing processes from interfering with each other.

Why Memory Management?

With multiple processes in modern systems, the OS must efficiently allocate and deallocate memory, protect process memory spaces, and provide the illusion of unlimited memory through virtual memory techniques.

Address Binding

Programs reside on disk as binary executable files. To execute, they must be loaded into memory and placed within a process context.

Types of Address Binding

1. Compile Time

  • If memory location is known at compile time, absolute code is generated
  • If starting location changes, code must be recompiled
  • Example: MS-DOS .COM programs

2. Load Time

  • If memory location is not known at compile time, relocatable code is generated
  • Final binding is delayed until load time
  • If starting address changes, only reload is necessary

3. Execution Time

  • Binding delayed until run time
  • Process can be moved during execution from one memory segment to another
  • Requires hardware support (base and limit registers)
  • Most modern systems use this approach

Logical vs Physical Address

Logical Address (Virtual Address)

  • Generated by the CPU
  • Address seen by the program
  • Also called virtual address

Physical Address

  • Actual address in memory
  • Loaded into memory-address register
  • Address seen by memory unit

Key Point

Logical and physical addresses are the same in compile-time and load-time binding schemes. They differ in execution-time binding scheme.

Memory Management Unit (MMU)

Hardware device that maps logical addresses to physical addresses at runtime.

Simple MMU scheme: Relocation Register Physical Address = Logical Address + Base Register Value Example: Base Register = 14000 Logical Address = 346 Physical Address = 14000 + 346 = 14346

Swapping

A process can be temporarily swapped out of memory to a backing store (disk) and then brought back into memory for continued execution.

Why Swapping?

  • More processes than available memory
  • Improve CPU utilization by time-multiplexing
  • Allow processes larger than physical memory

Swapping Process

  • Swap Out: Move process from memory to disk
  • Swap In: Load process from disk to memory
  • Major part of swap time is transfer time
  • Transfer time is proportional to memory space swapped

Issues with Swapping

  • Very expensive (disk I/O is slow)
  • Process might be swapped to different location
  • Must handle pending I/O operations
  • Modern systems use it sparingly (prefer paging)

Contiguous Memory Allocation

Memory is divided into several fixed-sized partitions. Each partition contains exactly one process.

Fixed Partitioning

  • Memory divided into fixed-size partitions at system generation time
  • Each partition can hold one process
  • Problem: Internal fragmentation

Variable Partitioning

Partitions are created dynamically based on process size.

Allocation Strategies

1. First Fit

  • Allocate the first hole that is big enough
  • Fast - stops searching as soon as adequate hole found
  • ✅ Simple and fast
  • ❌ Creates small holes at beginning of memory

2. Best Fit

  • Allocate the smallest hole that is big enough
  • Must search entire list (unless sorted by size)
  • ✅ Minimizes wasted space
  • ❌ Slowest
  • ❌ Creates smallest leftover holes (difficult to use)

3. Worst Fit

  • Allocate the largest available hole
  • Must search entire list
  • ✅ Leaves larger leftover holes (more usable)
  • ❌ Poor performance in simulations
Example Memory State: Holes: 100KB, 500KB, 200KB, 300KB, 600KB Process needs: 212KB First Fit: 500KB (first adequate hole) Best Fit: 300KB (smallest adequate hole) Worst Fit: 600KB (largest hole)

Performance Comparison

First fit and best fit are generally better than worst fit in terms of both time and storage utilization. First fit is typically faster.

Fragmentation

External Fragmentation

  • Total memory space exists to satisfy request
  • But it's not contiguous
  • Occurs in variable-sized partition schemes
  • Example: 1000KB free but in 10 chunks of 100KB each

Internal Fragmentation

  • Allocated memory is larger than requested memory
  • Wasted space inside a partition
  • Occurs in fixed-sized partition schemes
  • Example: Process needs 18KB but gets 20KB partition (2KB wasted)

50-Percent Rule

Statistical analysis suggests that, given N allocated blocks, another 0.5N blocks will be lost to fragmentation. This means 1/3 of memory may be unusable!

Solution: Compaction

  • Shuffle memory contents to place all free memory together
  • Only possible with dynamic relocation (execution-time binding)
  • Very expensive (must stop all processes)
  • Alternative: Permit logical address space to be noncontiguous → Paging!

Paging

Paging is a memory management scheme that eliminates the need for contiguous allocation and thus eliminates external fragmentation.

Basic Concept

  • Physical memory: Divided into fixed-size blocks called frames
  • Logical memory: Divided into blocks of same size called pages
  • Page size is typically a power of 2 (512B to 16MB)
  • Common sizes: 4KB, 8KB

How It Works

1. Process of size n pages needs n frames 2. OS finds n free frames anywhere in memory 3. OS loads process pages into frames 4. OS maintains page table to map logical → physical addresses

Address Translation

Logical Address = (page number, page offset) Page Number (p): Index into page table Page Offset (d): Combined with base address to get physical address Physical Address = (frame number, page offset) Example (4KB pages): Logical address: 8196 Page size: 4096 (4KB) Page number = 8196 / 4096 = 2 Offset = 8196 % 4096 = 4 If page 2 maps to frame 7: Physical address = (7 * 4096) + 4 = 28676

Page Table

  • One page table per process
  • Stored in main memory
  • Page Table Base Register (PTBR) points to page table
  • Page Table Length Register (PTLR) indicates size

Advantages of Paging

  • ✅ No external fragmentation
  • ✅ Easy to allocate (any free frame)
  • ✅ Easy to swap (write any page to disk)
  • ✅ Allows sharing of pages between processes

Disadvantages of Paging

  • ❌ Internal fragmentation (last page)
  • ❌ Overhead of maintaining page table
  • ❌ Memory access time increases (need to access page table first)

Translation Lookaside Buffer (TLB)

To speed up paging, we use a special fast-lookup hardware cache called TLB.

How TLB Works

  • Small, fast associative memory
  • Stores recent page-to-frame translations
  • Typical size: 64 to 1024 entries
  • Search time: < 10 nanoseconds

Address Translation with TLB

1. CPU generates logical address (page p, offset d) 2. Check if page p is in TLB If TLB Hit: - Get frame number from TLB (fast!) - Access physical memory If TLB Miss: - Access page table in memory (slow) - Get frame number - Update TLB with this translation - Access physical memory Effective Access Time = (TLB access time) + (Memory access time) But only if 100% TLB hit rate

TLB Hit Ratio

Hit Ratio = 80% (typical) TLB access time = 10ns Memory access time = 100ns Effective Access Time (EAT): = 0.80 × (10 + 100) + 0.20 × (10 + 100 + 100) = 0.80 × 110 + 0.20 × 210 = 88 + 42 = 130ns Without TLB: 200ns (access page table + access memory) With TLB: 130ns (35% improvement!)

Segmentation

Segmentation is a memory management scheme that supports the user's view of memory. A program is a collection of segments.

What is a Segment?

  • Logical unit such as: main program, procedure, function, method, object, local variables, global variables, common block, stack, symbol table, arrays
  • Segments vary in size
  • Segments are identified by segment number

Logical Address

Logical Address = (segment number, offset) Segment number: index into segment table Offset: should be between 0 and segment limit

Segment Table

  • Each entry has: base (starting physical address) and limit (length of segment)
  • Segment-table base register (STBR) points to segment table
  • Segment-table length register (STLR) indicates number of segments

Advantages

  • ✅ Matches programmer's view of memory
  • ✅ Easy to share code/data segments
  • ✅ Protection easier (segment = logical unit)
  • ✅ No internal fragmentation

Disadvantages

  • ❌ External fragmentation (variable-sized segments)
  • ❌ Allocation algorithms needed (first-fit, best-fit)

Segmentation with Paging

Combine advantages of both: segment each process, then page each segment!

Intel x86 Architecture

  • Supports both segmentation and paging
  • Logical address → segment table → page table → physical address
  • Each segment has its own page table

Benefits

  • ✅ Logical organization (segmentation)
  • ✅ No external fragmentation (paging)
  • ✅ Efficient memory use

Common Interview Questions

1. What is the difference between paging and segmentation?

Answer: Paging divides memory into fixed-size pages (hardware perspective), while segmentation divides memory into variable-size segments (programmer's perspective). Paging has no external fragmentation but has internal fragmentation. Segmentation has external fragmentation but no internal fragmentation.

2. Why is page size usually a power of 2?

Answer: It simplifies address translation. With power of 2, we can use bit shifting instead of division/modulo operations. The lower bits become the offset, upper bits become the page number.

3. What causes internal fragmentation in paging?

Answer: The last page of a process may not be completely filled. If process size is not a multiple of page size, the remaining space in the last page is wasted.

4. How does TLB improve paging performance?

Answer: TLB caches recent page table entries. Since programs exhibit locality (access nearby addresses), TLB hit rates are typically 80-98%, dramatically reducing memory access time.

5. Why is compaction expensive?

Answer: Compaction requires:

  • Stopping all processes
  • Moving large amounts of memory
  • Updating all pointers and addresses
  • Can take several seconds in large systems

Summary

Memory management is crucial for OS performance:

  • Contiguous allocation: Simple but suffers from fragmentation
  • Paging: Eliminates external fragmentation, most widely used
  • Segmentation: Logical organization, supports user view
  • TLB: Critical for paging performance
  • Modern systems: Use paging with TLB, sometimes combined with segmentation
